Figma is the most powerful design canvas there is — and it’s already your source of truth. The one thing it lacks is AI control.

figma-ds is that control layer. The AI works directly in your live Figma file — with your components, under your rules — not in a separate tool that produces a second source of truth.

The short version

Why this exists, what it is, how it runs.

01 / WHY

Consistency is the hard part

A design system is hundreds of small decisions — what things are called, how they’re built, when something becomes reusable, what gets documented. Teams re-make those decisions every week, slightly differently each time. That’s how brands drift and quality erodes.

figma-ds makes each decision once — then applies it every time, for everyone.

02 / WHAT

A team of eight AI specialists

Eight skills for Claude that cover the full life of a design system: laying the foundations, building components and screens, writing the documentation, and running the quality checks that keep it all in sync.

Like a meticulous systems designer who never forgets a convention — available to the whole team, on demand.

03 / HOW

It learns your system

The toolkit ships knowing the craft, not your brand. Each project keeps a living profile — your colors, your conventions, your past decisions. The AI reads it before every task, and records new decisions after.

The more you use it, the more it works like one of your own.

The mental model

You describe the task. The right skill takes it.

Each capability ships as a “skill” — a playbook the AI follows. You rarely pick one by name: describe what you want, the coordinator routes it to the right specialist, and every specialist consults your project profile before it touches the file.

Documentation isn’t an afterthought here. Every component is documented in three layers — the component itself, its short description, and a visual spec sheet right on the canvas — and each layer is kept honest by a different skill.

Two habits are built into every workflow: read the project profile first, and write lasting decisions back when the task lands. That feedback loop is what turns a generic toolkit into one that knows your system.

Capabilities

What is this system capable of?

Eight specialists, grouped by the job they do for you.

Foundation

everything below the component layer
01figma-tokens
Lays the foundation: your colors, typography, and spacing as a single source of truth every component draws from. Change it once — it updates everywhere.

Build

make the thing
02figma-component-build
Builds or fixes a single component — a button, a card, a form field — with all its sizes, states, and options, structured to scale.
03figma-screen-build
Assembles full screens from the components you already have — building with the official kit instead of redrawing from scratch.

Document

make it legible to everyone else
04figma-component-document
Writes the spec sheet that sits beside each component: what it is, when to use it, and what options it offers.
05figma-doc-verify
The fact-checker: finds documentation that no longer matches reality after things change — and repairs it.

Audit & maintain

find drift, fix it safely
06figma-system-audit
The detective: finds duplicates and near-duplicates across the system and proposes what to merge or clean up.
07figma-execute-audit
The fixer: works through that cleanup list, choosing the lightest safe way to handle each item.

Orchestrate

the front door
08figma-design-system
The front door: describe the task, it dispatches the right specialist. The work lives in the other seven.
Quick start

From zero to your first build.

Four steps. The only real setup is the project profile — that’s what makes the toolkit speak your system’s language.

1

Install the plugin

Add the marketplace once, then install. You’ll need read access to the mwulff-mode/claude-plugins repo. Restart Claude Code (or run /reload-plugins) afterward.

> /plugin marketplace add mwulff-mode/claude-plugins
> /plugin install figma-ds@mode
2

Create your project profile

The skills read project facts from a per-project profile. Copy the bundled template into your project’s memory folder and fill in the file key, brand, type ramp, and conventions. <project> is your repo path with slashes turned to dashes.

# the template ships inside the plugin (plugins/figma-ds/)
mkdir -p ~/.claude/projects/<project>/memory
cp project-profile.template.md ~/.claude/projects/<project>/memory/project_profile.md
3

Just describe the task

You don’t need to memorize skill names — say what you want and the right one triggers. A few that work well:

“Set up tokens for a new design system” “Build a Button component with variants” “Build this screen from the screenshot” “Audit the system for duplication” “Are our specimens up to date?”
4

Let it learn your system

Every skill reads the profile before it starts and writes durable decisions back when it finishes — a component promoted to a template, a new variant axis, a naming call. The more you use it, the less you re-explain.

One writer owns the canonical profile; teammates read the same source of truth. Keep brand-specific facts in the profile, never in the skills — that’s what keeps the toolkit portable.
