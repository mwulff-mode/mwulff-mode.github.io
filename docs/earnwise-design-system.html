    The EarnWise Design System

    One page to show every token, component, and interaction pattern currently wired into the Flutter app. As of sub-project 1 the token layer is two-tier (primitives plus semantic names), and six new shared widgets cover the patterns every screen will adopt in sub-projects 2 through 6.

    Overview

    What's in, what's not

    EarnWise now has a two-tier token layer: private primitives (_s4, _r16) feed semantic names (AppSpacing.cardPad, AppRadius.card) that every screen should reference. On top of the tokens sit the old movement primitives (PressScale, PhysicalPress, RewardGlow, AnimatedCounter, Breathing, Haptics) and, new in this sub-project, six shared widgets (Surface, CategoryIconSquare, ListRow, VerticalTile, SectionHeader, StatBubble) that capture the patterns repeated across every screen.

    Source of truth

    This page is the visual tour. The canonical reference that screens and widgets must read before any UI work is docs/design-system.md, pointed at from CLAUDE.md. Code lives under flutter_app/lib/theme/ and flutter_app/lib/widgets/. If a value isn't in those two folders, it isn't part of the system yet.

    Foundations

    Motion & haptics

    A 5-tier duration scale, 4 named curves, one spring preset, and a strict haptic policy. Defined in lib/theme/motion.dart and lib/services/haptics.dart. The PressScale widget is the single entry point for spring-driven press feedback.

    AppDurations · AppCurves · AppSprings

    Duration scale

    instant
    120 ms
    Press snap-back, micro feedback.
    short
    220 ms
    Toggles, tiny state flips (currency pill, nav tab).
    medium
    320 ms
    Default state changes (task → completed, unlock).
    long
    480 ms
    Page transitions, entrance reveals.
    hero
    900 ms
    Multi-beat moments (ring fill, gift reveal, RewardGlow).

    Curves

    warmOut
    Default deceleration. Entrances, reveals.
    warmInOut
    Symmetric. Reversible toggles.
    pop
    Slight overshoot. Reward flourishes.
    gentle
    Idle / breathing motion only.

    AppSprings.pressSettle: mass 1, stiffness 300, damping ratio 0.85. Underdamped for a confident settle. Drives PressScale and PhysicalPress.

    PressScale · lib/widgets/press_scale.dart · tap the card

    Word games
    Wordle, Scrabble GO
    scale 0.97 · no haptic · spring settle

    What it does

    • Spring scale: child snaps to pressedScale on press-in via pressSettle, returns on release
    • brightOnPress: translucent white overlay (15% by default) clipped to pressedBorderRadius
    • haptic: fires once on press-in via HapticIntensity enum
    • enabled: mirrors button disabled state, kills both animation and haptic
    • a11y: respects MediaQuery.disableAnimations (motion off, haptic and onTap still fire)

    Used on choice cards (AppCard wraps itself when onTap is set), the welcome email pill, the conversational home card, and small chrome targets. Primary CTAs moved to PhysicalPress, see the next plate.

    PhysicalPress · lib/widgets/physical_press.dart · tap to feel it sink

    Continue with Google
    Continue with Apple
    68 px face · 6 px depth · stadium radius

    Why a custom button

    The primary CTA needed to feel physical. A scale-based press on a flat rectangle still felt like a web button. This idiom layers the face over a solid offset shadow and on press-in translates the face down by depth px so it visibly sinks into the shadow. Mirrors the "pushable card" pattern from Cash App, Pinterest, Duolingo.

    Recipe

    • backgroundColor face fill, for teal CTAs: AppColors.primary
    • shadowColor darker shade, for teal CTAs: AppColors.primaryDark
    • depth 6 px default (5 for the Apple button)
    • height 68 px, pill radius height / 2
    • haptic HapticIntensity.confirm on press-in
    • enabled fades opacity to 0.45 and kills input when false
    • spring AppSprings.pressSettle, same as PressScale

    All 5 primary CTAs in the app (welcome Google / Apple, trust carousel, onboarding Continue, onboarding That's me) use PhysicalPress. AppButtonStyles is still defined but currently has no call sites. See the drift register.

    RewardGlow · lib/widgets/reward_glow.dart · celebration flourish

    ★
    pop (0-300) · halo (100-700) · warmOut (300-900)

    Three-beat choreography

    Wraps any child. When its controller fires play(), a 900 ms flourish runs over three overlapping beats. The child scales up on pop, a radial halo fades in behind it expanding from 80 percent to 140 percent, then the child settles back on warmOut.

    • Beat 1 0 to 300 ms, child 1.0 to 1.06, pop curve
    • Beat 2 100 to 700 ms, halo alpha 0 to 0.5 to 0, scale 0.8 to 1.4
    • Beat 3 300 to 900 ms, child 1.06 to 1.0, warmOut

    Drive it via a RewardGlowController (a ChangeNotifier). Home has two instances: _giftGlow on the welcome gift badge and _ringGlow that fires on the rising edge when goal progress crosses 100. The halo uses AppColors.accent by default and may overflow the parent bounds on purpose.

    AnimatedCounter · lib/widgets/animated_counter.dart

    $47.25
    interpolates to the new value on every value change

    Value transitions

    A self-contained counter. Every time its value prop changes, it interpolates from the previous display to the new one over AppDurations.hero, curved with warmOut. Integer output formatted by a caller-supplied format function so the same widget works for Stars and dollar balances.

    First build snaps to the current value with no count-up. Mid-animation updates capture the current interpolated value as the new start, so successive rewards chain smoothly without visual jumps.

    Currently used on the home balance row.

    Haptics policy · lib/services/haptics.dart

    Every haptic in the app routes through the Haptics service. No raw HapticFeedback.* calls anywhere else in lib/. The policy was revised after the first user test. Chrome interactions used to fire a soft tick, and they no longer fire anything.

    ✓ Fires haptic
    • confirm: light impact. Primary CTAs (Continue with Google / Apple, "Let's get started", "That's me", future Cashout)
    • reward: light impact. Single task completion
    • milestone: medium impact. Goal completed, all-tasks unlocked
    • celebrate: medium impact. Welcome gift reveal, legend reached. Per-session guard via CelebrateMoments.* ids
    • warning: heavy impact. Form errors, blocked actions (no call sites yet, reserved for future error states)
    × No haptic
    • Nav switches: bottom tab change
    • Currency toggle: $/★ pill
    • Conv card open: home to journey
    • AppCard rows: onboarding choices, game picker
    • Task card press-in: the visual transition is the confirmation
    • Back / close buttons: chrome interactions stay silent

    Haptics.tick() is deprecated and is now a no-op. It is kept only so any forgotten chrome call site doesn't fire selectionClick. Remove on sight.

    Breathing · lib/widgets/breathing.dart

    E

    Idle life

    A very quiet cosine-driven scale oscillation for elements that should feel alive when nothing is happening. Default 5s period, 0.015 amplitude (1.5%, barely perceptible). One peak per period, no opacity, no position. Used on the welcome screen logo.

    Disables on MediaQuery.disableAnimations.

    Motion

    Interaction patterns

    Three recipes cover almost every transition in the app.

    01 · Screen transition

    All route changes go through fadeRoute(), which now wraps CupertinoPageRoute. Every push gets the iOS-native slide-from-right with parallax on the outgoing screen and the swipe-back-to-pop gesture for free. The name is a legacy misnomer. The helper is no longer a fade.

    02 · Press feedback

    Two primitives cover every tap in the app. Primary CTAs use PhysicalPress, which renders its own pill button with an offset shadow and sinks the face into it on press, firing HapticIntensity.confirm. Everything else (choice cards via AppCard, chrome buttons, the home conversational card) wraps in PressScale for a 0.97 shrink with no haptic. Both share AppSprings.pressSettle.

    03 · Celebration

    Hero reward moments use RewardGlow driven by a RewardGlowController, paired with Haptics.celebrate(momentId). The visual is a 900 ms three-beat pop, halo, settle sequence. The haptic fires at most once per app run per moment id. Canonical ids live in CelebrateMoments: welcomeGift and legendReached.

    04 · Bottom sheet

    showAppBottomSheet() is the single entry point. Cream background, 24 px top corners, 4 by 40 grab handle, safe-area bottom inset. Dismissable by drag or backdrop tap (Flutter default).

    05 · Transient feedback

    showAppToast() for short confirmations. Top of screen, fade in long, hold 3.5 s, fade out long, remove. Not a snackbar. No action slot, no persistent dismiss.

    Known drift

    Drift register

    Six items tracked. Five are now closed; one remains deferred until there's a real use case.

    01
    No button style constants Superseded
    First closed by AppButtonStyles.primary / primaryOutline. The visual then evolved to the PhysicalPress idiom (pill face over offset shadow) and all 5 CTAs migrated there. AppButtonStyles is still defined but has no call sites. Kept as a reference recipe for any future flat CTA.
    02
    No card decoration Closed
    Resolved in two passes. AppCard covers the selectable choice-card pattern; sub-project 1 added Surface as the raised-card primitive every new feature card composes from. Inline Container(decoration: ...) in screens is now drift, migrated in sub-projects 2 through 6.
    03
    No named text styles Closed
    Resolved by AppText (14 named getters after sub-project 1). Sub-project 1 added title (22/700) as the canonical heading and deprecated sectionTitle as a forwarder. sheetTitle is scheduled for migration in sub-project 2.
    04
    Raw pixel values in screens Closed
    Sub-project 1 shipped the two-tier token layer: AppSpacing, AppRadius, and AppElevation all expose semantic names backed by private primitives. Raw SizedBox(height: N) and EdgeInsets.all(N) in screens is now drift, migrated in sub-projects 2 through 6.
    05
    No shared composition widgets Closed
    Sub-project 1 added six reusable widgets for patterns every screen repeats: Surface, CategoryIconSquare, ListRow, VerticalTile, SectionHeader, and StatBubble. Sub-projects 2 through 6 replace per-screen helpers (_taskCard, _earnTile, _buildContinueCard) with these primitives.
    06
    No adaptive dialog Deferred
    Zero alerts today, so no infrastructure yet. Build showAppDialog() when the first real use case arrives.
